AYönetici özeti

Bu, incelediğim küçük ölçekli Swift projelerinin üst yüzdelik diliminde bir kod tabanı. Yorumlar ne yaptığını değil neden öyle yapıldığını anlatıyor ve çoğu ölçüme dayanıyor — “Eyüpsultan'da 34 kaydın 32'si”, “render 2.14 ms/kare”, “15 ilin medyanı”. Alan çekirdeği (PrayerTimesCalculator, SolarMath, Qibla) saf Foundation; ağ yok, çerçeve bağımlılığı yok, belirlenimci. Widget ve saat hedeflerinin bu kadar sade olabilmesinin sebebi tam olarak bu karar.

Geçersiz durumların temsil edilemez kılınması bilinçli ve tutarlı: DailyPrayerTimes eksik sözlükle kurulamıyor, bu yüzden subscript'teki zorlama açma güvenli; QadaLedger borcu sayaç tutmak yerine üç bileşenden türetiyor, bu yüzden çift sayma mümkün değil; LocationState ve MosqueSearchState “boş liste” ile “hata” ile “yükleniyor”u ayırıyor.

Buna karşılık üç yapısal zayıflık var ve üçü de aynı yerden geliyor — projenin en yeni parçası olan saat tarafı, iOS tarafındaki titizlikle aynı seviyeye getirilmemiş. İki yayın engelleyici madde de orada. Her ikisi de kod değil, hedef yapılandırması; toplam düzeltme süresi on dakikanın altında ama ikisi de sessiz başarısızlıkla sonuçlanıyor, yani test cihazında fark edilmeden App Store'a gidebilir.

Özellikle dikkat çeken

Tools/check/targets.sh her hedefi kendi dosya kümesiyle ve kendi SDK'siyle tip denetiminden geçiriyor, dosya listesini de pbxproj'daki membershipExceptions'tan okuyor. Paket kullanmadan çok hedefli bir projede üyelik hatalarını yakalamanın doğru yolu bu; çoğu ekipte bu denetim hiç yok. MemberImportVisibility bayrağının hem Xcode'da hem betikte açık tutulması ayrıca isabetli.

Güçlü yanlar

  • Alan çekirdeği gerçekten çerçeveden bağımsız. Bu yüzden Tools/validate ve Tools/tests Xcode olmadan koşabiliyor, doğruluk 15 ile karşı ölçülebiliyor.
  • WidgetKit bütçe disiplini örnek düzeyde. Girdiler yalnızca vakit geçişlerinde üretiliyor; geri sayım ve ilerleme Text(timerInterval:) / ProgressView(timerInterval:) ile kendi kendine ilerliyor. SharedLocationStore.save aynı konumu yeniden yazarken reloadAllTimelines çağırmıyor.
  • Görünüm/kabuk ayrımı araca hizmet ediyor. PrayerTimesContent, QiblaContent, NearbyMosquesContent, TrackingContent, WatchPrayerTimesContent — hepsi servislerden arındırılmış, ImageRenderer ile basılabiliyor. Bu bir stil tercihi değil, kurulmuş bir doğrulama hattı.
  • Erişilebilirlik sonradan eklenmiş gibi durmuyor. Satırlar tek cümlede birleştiriliyor, pusula değeri 15°'ye yuvarlanarak erişilebilirlik ağacının saniyede onlarca kez yeniden kurulması engelleniyor, Dynamic Type için tablo blok düzenine geçiyor.
  • Singleton kötüye kullanımı yok. Hiçbir yerde değişken durum tutan .shared nesnesi yok; paylaşılan her şey ya durumsuz bir ad alanı ya da sahibi belli bir @State.

Zayıf yanlar

  • Xcode projesinde test hedefi yok. Gerçek testler var ama proje dışında ve tek bir tipi kapsıyor; xcodebuild test ile CI'ya bağlanamıyor.
  • Widget veri senkronizasyonunun sorumluluğu bölünmüş. Elle seçim LocationProvider.setMode'da, otomatik konum PrayerTimesViewModel.apply'da kaydediliyor — yani bir sekmenin görünüm modeli widget'ın veri kaynağı durumunda.
  • Statik ad alanları dikişleri kapatıyor. MosqueFinder, LiveActivityController, SharedLocationStore ve kardeşleri enum + static; ağ, Live Activity ve paylaşılan depo taklit edilemiyor.
  • Swift 5 dil kipi, hedefler arası tutarsız eşzamanlılık ayarı. Saat hedeflerinde SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor açık, iOS ve widget hedeflerinde değil.
  • Saat tarafı yarım. Konum izni metni yok, gizlilik bildirimi yok, izin reddedildiğinde kullanıcıya hiçbir şey söylenmiyor.

Watch iletişim kararı: doğru

Bunu ayrıca vurgulamak istiyorum çünkü çoğu proje burada yanlış yapıyor. Namaz vakitleri koordinat ve tarihten hesaplanabilir; bu yüzden telefondan saate veri taşımanın hiçbir kazancı yok, buna karşılık gerçek bir maliyeti var: WCSession eşleşme durumu, erişilebilirlik, yeniden bağlanma ve senkron dışı kalma. Anahtarlara platform öneki koymak bugün bedava, sonra değil.

Sorun
Hesap, yerel gece yarısı anını çapa alıyor: calendar.date(from: DateComponents(year:month:day:)) ile midnight bulunuyor, sonuçlar midnight.addingTimeInterval(hours * 3600) ile üretiliyor. Yaz saatine gece yarısı geçen bölgelerde yerel 00:00 o gün hiç var olmaz; Foundation bu durumda bir sonraki geçerli anı (01:00) döndürüyor ve bütün gün bir saat kayıyor.

Sonuç

enum LiveActivityController {
    private static let scheduleCount = 3
    /// Yenilemeler seri: `endAll` + `request` atomik degil, ust uste
    /// binen iki cagri birbirinin etkinligini silebiliyor.
    private static var inFlight: Task<Void, Never>?

    static func refresh(with contents: [PrayerActivityContent],
                        enabled: Bool, leadMinutes: Int) async {
        let previous = inFlight
        let task = Task { @MainActor in
            await previous?.value
            await apply(contents: contents, enabled: enabled,
                        leadMinutes: leadMinutes)
        }
        inFlight = task
        await task.value
    }

                              enabled: Bool, leadMinutes: Int) async {
        await endAll()
        guard enabled, isAvailable, !contents.isEmpty else { return }
        // ... mevcut govde aynen
    }
}

descriptor(of:) yardımcısı dört dosyada tekrarlanıyor — PrayerTimesView, QiblaView, NearbyMosquesView, ImsakiyeView — üstelik üç farklı gövdeyle (biri tüm durumları, ikisi yalnızca resolved'ı kodluyor). Hepsinin yorumu aynı: “onChange için sade bir kimlik: LocationState eşitlenebilir değil.”

Oysa LocationState'in bütün ilişkili değerleri zaten Equatable: Coordinate Equatable, String Equatable. Tek kelime ekleyince Swift uyumu sentezliyor ve dört yardımcı da, dizgeye dönüştürme de gereksiz kalıyor. Bu tekrar “şu an benzeyen iki farklı şey” değil, gerçekten aynı kavram — soyutlama uydurmuyoruz, eksik uyumu ekliyoruz.

Önce — dört dosyada

enum LocationState {
    case idle, requesting
    case resolved(Coordinate, name: String)
    case denied
    case failed(String)
}

// ...her gorunumde tekrar:
.onChange(of: descriptor(of: location.state)) { _, _ in
    viewModel.apply(location.state)
}

private func descriptor(of state: LocationState) -> String {
    switch state {
    case .idle: return "idle"
    case .requesting: return "requesting"
    case .denied: return "denied"
    case .failed(let m): return "failed:\(m)"
    case .resolved(let c, let n):
        return "resolved:\(c.latitude),\(c.longitude),\(n)"
    }
}

Sonra

enum LocationState: Equatable {
    case idle, requesting
    case resolved(Coordinate, name: String)
    case denied
    case failed(String)
}

// ...her gorunumde:
.onChange(of: location.state) { _, _ in
    viewModel.apply(location.state)
}

// descriptor(of:) dort dosyadan da silindi (~40 satir).
